# GameTuner

完全离线的 Windows 游戏性能日志分析与画质对比工具。软件只读日志、给出手动调整建议；
不启动或关闭游戏、不写游戏配置、不连接 NVIDIA MCP、不上传日志、不调用 AI。

## 工作方式

1. 打开窗口时自动识别正在运行的游戏（按可见窗口排除本程序、系统组件、工具与启动器），填入游戏名和进程；识别不到时会说明原因，也可以点“选择游戏进程…”手动改选。同时自动读取硬件、当前分辨率和支持游戏的真实画质配置。
2. 进入实际游玩画面后，点击“开始新采集”，通过 PresentMon 采集所选进程的逐帧数据，同时采样 CPU、GPU 和显存；点击“停止并分析”整理本轮日志并建立基线。每轮都显式开始新采集，也可直接导入已有日志。
3. 查看瓶颈、整体降档方向和单项建议，在游戏里手动调整。
4. 调整游戏后重新采集，再分析第二轮，对比平均帧率与低帧变化。
5. 可继续导入第三、第四、第五、更多日志，不限轮次；点击轮次按钮查看对应配置。
6. 平均 FPS 和有效 1% Low 都达标后，提示停止继续调整并保存本次方案。
7. 在“分享配置卡”预览并导出 PNG，展示实际硬件、画面设置、FPS、数据口径与采集时间。

“达标”表示已测片段符合玩家目标，不代表数学意义的全局最优或未来所有场景都达标。
软件不会继续强制三轮测试，也不会把未执行的建议当成已生效配置。

## 游戏兼容

不按游戏名称或 NVIDIA App 的可优化游戏名单限制。只要能提供支持格式的日志，
任意游戏名称都可以建立对比；不保证每款游戏或每个记录工具都能生成兼容日志。

目前支持：

- NVIDIA 性能 CSV：包含 `Timestamp (Elapsed time in seconds)` 和 `FPS`，
  可选 `FPS 1(%) Low`、CPU/GPU 利用率及显存字段。按采样时间加权统计。
- 逐帧耗时 CSV：例如包含 `MsBetweenPresents`、`FrameTime` 列。
  计算平均 FPS 和最慢 1% 帧的平均 FPS。
- RDR2 Benchmark 摘要：作为可选适配器，读取 `Pass` 和 P99 结果。
  P99 等效低帧不是精确 1% Low，不据此宣布目标已完全达成。

未识别、空文件、多个 PID、时间倒退的日志会明确报错，不生成虚假轮次。
同一内容的日志改名再导入也不会重复算轮次；同名文件产生新的内容可以重新分析。
缺少低帧或硬件信息时显示未知，不从平均 FPS 猜出 1% Low、显卡或显存瓶颈。

建议使用至少 3 分钟、相似场景的实际游玩片段。短日志可以导入，但会提示代表性不足；
不足 5 秒的片段不据此宣布目标已达成。
不同日志口径之间不直接宣称提升；分辨率、场景、驱动与后台程序变化也会影响比较。

## 手动建议

通用规则按 GPU、CPU、显存证据给出调整顺序。例如：

- 当前高档 → 建议先试中档。
- GPU 受限：先降体积效果，仍不达标再试反射或阴影；暂时保留纹理。
- GPU 受限且真实配置明确显示光追已开启：优先只关闭光追再复测；关闭状态不会触发这条建议。
- CPU 受限：优先试减物理、模拟、人群密度，不直接整套降低纹理或分辨率。
- 显存压力：先试减纹理占用。
- 缺少证据：只给保守单项试调，不编造具体游戏菜单、已验证增帧或当前档位。

整体预设与逐项调整是两种试验方式，选择一种即可；选项名称以游戏菜单为准。

## 本机配置读取

- 通过原生进程选择器手动选择游戏；可按进程名、PID 或窗口标题搜索，选择结果同时用于配置读取和 PresentMon 采集。
- Windows 后台只读获取 CPU、显卡、内存、可用显存和主显示器当前分辨率，不需要填写硬件。
- RDR2 从本机 `system.xml` 读取实际分辨率与已知画质项；007 First Light 从本机注册表读取已知画质项。
- 每次导入支持的日志前重新读取并保存本轮快照，不启动游戏、不写配置；历史轮次保持当时的记录。
- 可从玩家明确选择的 JSON、XML 或 INI 文件只读导入标量画质设置；保留原始设置名和值，不猜测档位或修改源文件。更新历史轮次说明仍需显式点击。
- 没有只读适配器、尚未生成配置或读取失败时，才需要手动补充实际画质。
- 主显示器分辨率不被冒充为所有游戏的实际渲染分辨率；支持的游戏优先使用配置文件中的值。
- 自动查找 NVIDIA 默认日志目录、指定日志目录和 RDR2 Benchmark，选择最新可用文件；仍保留手动选择作为回退。
- 实时采集文件保存在 `%LOCALAPPDATA%\GameTuner\captures`。PresentMon 只跟踪手动选择的游戏 PID，GameTuner 只停止自己启动的采集进程，不关闭游戏。

## 保存与分享

- 最近保存的对比记录：`%LOCALAPPDATA%\GameTuner\manual-analysis.json`。
- 各个目标的方案存档：`%LOCALAPPDATA%\GameTuner\manual-plans\*.json`。
- 下次启动自动展示最近保存方案；“载入已保存方案”可选择之前的目标记录。
- 保存只写本软件的记录，不把画质设置应用到游戏。
- 分享卡展示选中轮次的实测和玩家填写的实际配置，不展示完整日志路径或私密凭据。
- 无法读取的配置显示“未填写”，不会自动猜测。补充信息后可明确“更新本轮说明”。
- PNG 宽 1760 像素，高度随文字内容适配，在本机生成，没有云端上传。

## 运行

### 分享给玩家

发布 Windows 10/11 x64 自包含压缩包：

```powershell
.\scripts\publish.ps1
```

把生成的 `artifacts/release/GameTuner-win-x64.zip` 发给玩家。玩家完整解压后双击
`GameTuner.App.exe`，不需要安装 .NET、RTSS、NVIDIA App、FrameView 或 PresentMon。

程序会请求管理员权限：PresentMon 必须建立性能追踪（ETW）会话，Windows 只有在管理员权限
或加入「Performance Log Users」组时才允许。若以普通权限运行，采集会以 `access denied`
失败且不生成任何日志。因此 `GameTuner.App.exe` 会弹出一次 UAC 提示；请选择“是”，否则
实时采集不可用（仍可导入已有日志分析）。不需要采集时也可以只使用导入功能。
不要只复制 EXE；`Tools` 和自包含运行库是程序运行所需的一部分。发布脚本会拒绝包含
`WebApp` 的包，并验证随包 PresentMon 的 Intel 签名。

发布包携带官方 Intel PresentMon 2.3.1，采集器只从程序自己的 `Tools/PresentMon` 加载，
不会借用玩家电脑里已安装的软件。其来源、SHA-256 和 MIT 许可证见
`src/GameTuner.App/Tools/PresentMon/`。NVIDIA 显卡的利用率与显存采样使用显卡驱动提供的
`nvidia-smi`；这不是额外的采集软件安装要求，其他显卡可能暂时缺少这部分指标。

### 开发运行

开发环境需要 .NET 9。直接运行 `run.cmd`，或：

```powershell
dotnet restore GameTuner.sln --configfile NuGet.Config
dotnet run --project src/GameTuner.App/GameTuner.App.csproj
```

启动后直接显示原生 WPF 窗口，不启动 HTTP 服务或浏览器，也不需要 Node.js、npm、
WebView2 或 Chromium。进程选择、文件选择、保存和导出均使用原生对话框。

离线指应用运行和分析不联网；首次构建若本机没有依赖缓存，仍需先还原开发依赖。

## 验证

```powershell
.\tests\verify-ui.ps1
# 已还原依赖时：
.\tests\verify-ui.ps1 -SkipRestore
```

脚本构建 Release 并运行核心与原生 WPF 工作区测试，TRX 结果和分享 PNG 输出到
`artifacts/offline-verification`。覆盖真实文件解析、不限轮次、任意游戏名、
低帧缺失、目标达成、配置快照、存档/载入、进程选择、重复采集、原生模态/键盘操作和真实 PNG 导出。
原生窗口以 1180×780 和 960×680 渲染验收。
测试数据放在隔离临时目录，截图带 `test-data` 的内容不代表用户的真实实测。
本机 NVIDIA 集成与真实游玩不在脚本的默认验收范围内。

旧自动优化适配器和测试暂留作历史参考，不进入应用启动或交互链路。
实现方案见 `docs/decisions-offline-log-analysis.md`。

窗口右上角的“◐”按钮可切换浅色与夜间模式，主题选择保存在本机。
